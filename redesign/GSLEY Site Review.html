GSLEY Digital · UX & design review · 28 October 2026

gsleydigital.com: what works, what to change, and how to stop coming back to it.

Scope: the live WordPress site at gsleydigital.com (Home, Services, Tools, a tool page, Automation & RevOps, About, Contact) and the repository chudeway89/gsleydigital-with-Claude at commit ddc5bbf.

Verdict. The design system is sound and the voice is consistent. The site doesn't need a redesign. What hurts it is a set of publishing errors: placeholder text that's live, numbers that contradict each other between pages, a "Book a Discovery Call" button that doesn't book anything, and a mobile menu below current standard. Each one is cheap to fix. The bigger structural issue is that the code running the live site isn't in the repository. Until it is, every fix depends on whoever has server access.

1. Live site vs. repository

The live site is ahead of the repository, not behind it. Production has the Services index, Automation & RevOps, AI Adoption Programmes, and ten tool pages, two of them paid. None of these exist in the repo. The repo holds the Phase 1 HTML design reference and planning documents only. There's no theme, no plugin, and no theme.json.

P0The WordPress theme and plugin aren't version-controlled

The live site loads a custom gsley-seo plugin and a custom theme. Neither is in the repository, so there's no history, no rollback, and no way for anyone else to apply a fix safely.

FixCommit the theme folder and the GSLEY plugin to the repo (wp-content/themes/gsley, wp-content/plugins/gsley-*). Deploy from Git from then on.

Owner / developer · one-off

P2Repo reference pages have drifted from production

For example, repo contact.html still links /insights (it 404s), the repo has no pages for the 3 extra services or the 9 extra tools, and repo copy differs slightly in places (founder heading).

FixTreat the files in redesign/ as the current reference and retire the Phase 1 HTML once the theme is committed.

2. What works — keep it

  • The "Engineered Precision" system: Source Serif 4 / Inter / JetBrains Mono, ink-on-paper, a single teal accent, ink band for Market and teal band for Digital. It's distinctive and reads as institutional rather than agency.
  • The hero thesis line. It's clear, memorable, and gives the visitor a reason to read on.
  • Answer-first diagnostics as the main lead route, with a free score before the email ask.
  • Service pages: gap, then named archetype method, then scope, outcomes, and FAQ. Automation & RevOps is the strongest page on the site.
  • No fake logos, testimonials, or invented statistics. "Client roster — disclosed on request, under NDA" is the right call.
  • The "In one paragraph" answer block and the FAQ blocks are good material for AI-search citation, and llms.txt is in place.
  • The three-step "What happens next" on Contact sets expectations well.
  • WhatsApp as a first-class channel suits the audience.

3. Fix before anything else (P0)

P0Placeholder text is live on Home and About

Visitors see "[ Founder photo Chukwudi Eze 4:5 portrait ]" in the founder section of both pages. It's the most visible credibility leak on the site.

FixUpload the portrait and add alt text. Until then, the v2 component shows a "CE" monogram instead of printed instructions, so no placeholder text can reach the page again.

WP: Media + founder pattern · redesign/gsley.css .photo

P0The site title is wrong in every browser tab and search result

The homepage title is "Gsley Digital AI | Marketing | PR | Health -", with a trailing dash and a "Health" pillar that doesn't exist. Every inner page inherits it, e.g. "Tools - Gsley Digital AI | Marketing | PR | Health".

FixSet the site title to "GSLEY Digital" and the tagline to "Growth & AI Studio". Use the title format "%page% — GSLEY Digital" and the homepage title "GSLEY Digital — Growth & AI Studio".

WP: Settings → General + SEO plugin

P0Pages contradict each other on numbers

Home says "Eight diagnostics". Tools says "Ten tools" in the H1, "Eight free diagnostics" in the meta, and "the other seven" in the closing line. About says "eight free diagnostics". Services says "Nine doorways" but lists eight, numbered M-01 to M-04 then M-06, with no M-05. It also says "Thirteen" Market services, while eleven Market service pages exist.

FixNever type counts into copy. In v2 they're calculated from one tools list (data-count). In WordPress, the plugin should output the count with a shortcode or block binding, e.g. [gsley_count type="free-tools"].

WP: Home, Tools, About, Services copy · plugin

P0"Book a Discovery Call" doesn't book a call

It appears about four times per page, and every instance goes to /contact, which only has a brief form. A visitor who expects a calendar gets a form, and many will leave at that point.

FixAdd a Cal.com or Calendly link once in settings. Every booking button then opens the scheduler, and Contact shows an embedded calendar. With no link set, the buttons go straight to the brief form, labelled honestly.

site.js bookingUrl → plugin setting

P0Tool pages send no content without JavaScript

The served HTML of /tools/brand-authority-audit has no H1, intro, or tool, just header and footer. Search engines and link previews see an empty page, and if the script fails, so does the visitor.

FixRender the tool's title, one-paragraph description, time, output, and FAQ on the server. Let JavaScript add only the interactive part. Also check in a browser that all ten tools load and submit.

Plugin tool block: render.php

P0Two "Skip to content" links on every page

The theme and WordPress (or a plugin) each output one, so screen-reader users hear it twice.

FixKeep the theme's .skip-link and remove the other.

4. Web and mobile experience (P1)

P1The mobile menu is below standard

The menu drops inline and pushes the page down. The page behind it still scrolls, Escape doesn't close it, tapping a link leaves it in a half-open state, and the toggle is about 38px, under the 44px minimum.

Fixv2 uses a full-height panel with scroll lock, Escape to close, close on navigation, a 44px toggle that turns into an X, focus moved into the menu, and both main actions at the bottom.

gsley.css .mobile-nav · site.js

P1The WhatsApp button covers content on phones

The 56px floating button sits over text, form fields, and the footer at 375px wide, and there's no persistent route to the main conversion action.

FixOn mobile, replace it with a bottom action bar after the first scroll: the primary call to action plus WhatsApp, with safe-area padding. Desktop keeps the floating button.

gsley.css .action-bar

P1Contrast failures in key places

The hero's key line "We engineer the gap." uses #8895A7 on #FAF9F5, about 2.8:1, which fails WCAG AA. The same token is used for tool meta, ladder numbers, and card numbers. Ghost-button borders (#E5E2D8) are almost invisible.

FixThe new --ink-400 (#5F6B7C, 5.1:1) is for small informational text, and the hero line uses --ink-500. --ink-300 is kept for decoration only. Ghost borders are now #CFCBBE, and a darker teal (#0E7A70) is used for teal text on paper.

gsley.css tokens → theme.json palette

P1The homepage says the same thing three times

§01 Architecture, §02 Pillars in detail, and §03 Capability map each present the two pillars. Twelve sections, plus a "§ 03.5", make the page long, especially on mobile. The capability cards also show filled bars (5 of 7, 6 of 7) that look like a score with nothing behind them, which goes against your own no-invented-statistics rule.

Fixv2 merges these into one "Two pillars" section where every service is a link. The bar graphics are gone, the founder and credentials sections are combined, and sections are numbered §00–§07. The page is about 35% shorter.

Homepage v2.html

P1The brief form loses context and leads

The dropdown lists 9 of 17 services. "Begin a sprint" links arrive with nothing selected. There's no phone field in a WhatsApp-first market, no inline validation, no visible success or error state, and no spam protection.

FixThe dropdown is now built from the services list, grouped by pillar. /contact?service=google-ads preselects the service, a phone field is added, and errors show per field. There are sending, success, and failure states (failure keeps the message and offers WhatsApp), plus a honeypot and source tracking. Inputs are 16px, which stops iOS zooming in on focus.

Contact v2.html

P1Paid audits sit inside "free" messaging

The Tools page is framed as free, instant, and no sign-up, but lists two audits that charge $10 and $20. Everywhere else, pricing is on request. The mix muddies the offer.

Fixv2 separates them under "Live audits · free score, paid detail". The free count excludes them automatically.

7. Editing without coming back to the design

Three rules, enforced in the build, keep the site editable without design help:

  1. Every fact lives in one place. Email, phone, WhatsApp, booking link, socials, location, and hours go in a single "GSLEY Settings" screen in WP-admin. Header, footer, Contact, FAQ, and the WhatsApp button all read from it. Change the number once and it updates everywhere.
  2. Lists generate themselves. Services and tools are registered once. The footer, mobile menu, contact dropdown, tool grid, and every count are built from those registrations. Adding a tool adds it everywhere, and the "Eight diagnostics" line updates by itself.
  3. Layout is locked, words are open. Sections are synced, locked block patterns. You can edit any text or image in the block editor, but you can't break the grid, spacing, or mobile behaviour. New pages are built by inserting the existing patterns.

8. Decisions only you can make

  1. Location wording. An earlier brief asked for Lagos to be removed in favour of a global position. The live site still says "headquartered in Lagos" in the hero answer block, FAQ, footer, and contact. Keep it as is ("Lagos-based, working worldwide"), or switch to a global-only line? It's one setting in site.js plus two copy blocks.
  2. Scheduler. Choose Cal.com or Calendly and paste the link into bookingUrl. Until then the booking buttons go to the brief form.
  3. Email. The live site uses brief@gsleydigital.com, and an earlier brief asked for gsleydigital@gmail.com. I've kept brief@ because a domain address carries more trust. Make sure it's monitored.
  4. Toolkit tier. Publish the three toolkits or change the examples.
  5. Claims. Confirm you stand behind "deployed in 4–8 weeks", "Pipeline within 30 days", and "reply within one working day".
  6. Founder portrait. Supply the image and approve the alt text.
